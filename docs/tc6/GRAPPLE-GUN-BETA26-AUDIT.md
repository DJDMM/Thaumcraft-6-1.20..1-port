## Gun, payment and launch

The original item has stack size **1**, rarity **UNCOMMON**, rechargeable capacity **100** and normal charge HUD display. There is **no durability, ammunition, rope component consumption, held-use duration, cooldown or direct aura drain per shot**. Components belong to the crafting route. Charging uses the existing TC6 recharge route and `tc.charge`; the original `RechargeHelper.consumeCharge` has no creative exemption.

Every use plays the original `ice` sound at volume **3** and pitch **.8 + randomFloat*.1** and returns **SUCCESS**, including an empty gun. On the server, positive stored charge allows a hook spawn. Only an accepted native entity spawn costs **one charge** and sets byte `loaded=1`. This byte drives the item `type` model property; it is not ammunition and does not block another shot. Inventory updates clear exactly `loaded==1` to zero when the holder has no active map entry. Other inventory items, charge and tags are preserved. The original reequip check only reacts to its loaded/unloaded transition; a charge-only NBT change does not invent another equip animation.

`EntityThrowable` starts at `(playerX, playerEyeY-.10000000149011612, playerZ)`. The gun invokes the inherited living-entity launch with pitch, yaw, pitch offset **-5**, speed **1.5**, inaccuracy **0**. Legacy direction is `(-sin(yaw)*cos(pitch), -sin(pitch-5), cos(yaw)*cos(pitch))`, normalized through the old float square root. `EntityGrapple` forces the direct launch inaccuracy argument to zero. The base consumes its three Gaussian samples even when their multiplier is zero. It adds the thrower's X/Z velocity and, when airborne, Y velocity. There is no invented charge-up strength or random spread.

The post-launch muzzle offset uses `(yaw-.5)/180*3.141593f`: `-cos(angle)*.2f*handSign` on X and `-sin(angle)*.3f*handSign` on Z, with MAIN sign +1 / OFF sign -1. It additionally adds look.X to X and **literally look.Y to Z**. The unusual look.Y term is verified in released item bytecode and retained rather than silently corrected to look.Z.

## Projectile state machine

The existing ID is `thaumcraft:grapple`, size **.1×.1**, tracking **64 blocks**, update interval **20**, velocity updates enabled. The original render-distance predicate is strict squared distance **<4096**. Owner identity and hand are sent at spawn. The hook's own state begins MAIN hand, not pulling, no boost, previous-distance bucket zero, count zero, not yet bound and amplitude zero; the firing constructor then installs the actual hand.

The original calls its vanilla throwable update first. Flight uses an outline/block ray, no fluid ray hit, then an expanded native entity query. Entity candidate boxes grow by `.30000001192092896`; the first-frame temporary ignore-entity rule is the old `ticksExisted<2` algorithm, including its last-candidate `ignoredSeen` quirk. It is not replaced with the modern permanent `leftOwner` filter. Entity interception creates the old entity-position hit result: the anchor is the target's position, not the nearest surface intersection. A Nether portal follows the inherited portal route instead of anchoring.

An authoritative impact against either a block **or an entity** sets pulling, zeros all hook velocity, puts it at the hit point and sends entity status byte **6**. It causes **no entity damage and no block breaking**. An entity hit becomes a fixed point; the target is not followed. The support block is not a permanent permission or existence requirement, and there is no invented anchor material whitelist. Status 6 makes the client pulling and zeroes velocity. Modern tracked pulling state additionally lets a late native tracker see the actual current state; hand and owner are tracked too.

Movement adds current velocity to position, smooths rotation and applies drag **.99f**, or **.8f** in water. Gravity is **.03f** in flight and zero while pulling; ordinary no-gravity behavior remains. Original vanilla throwable water bubbles occur even for a stationary pulling hook. The reviewed implementation retains that emission and the inherited collision check during attached updates; it does not optimize either away merely because pulling is active.

A flying hook expires only **after age 30** (`ticksExisted>30`) or when no thrower exists. The check occurs after the inherited movement/impact, so a hit on that update can become attached before the flight expiry predicate. An attached hook has **no arbitrary lifetime/distance/stuck-count expiry**. Its unused bucket counter is retained as an observed counter, not turned into a new timeout.

One live hook is registered per owner on its first entity update, not immediately at item use. A new owner's hook removes the previous one at this binding step. Consequently re-fire is permitted while already loaded and costs another ordinary charge. Sneaking does **not** cancel flight; sneaking while pulling removes the active link and hook, with no extra payment or synthetic refund.

For an attached, non-sneaking thrower, the original server player floating counter is reset and fall distance becomes zero. Let `d` be the legacy float distance, and `q=d*(8-d)` when `d<8`, otherwise `q=d`; replace `q` by `max(1e-9,q)`. Acceleration is the hook-minus-thrower position divided by `q*5`. If its length exceeds **.25**, normalize and scale to **.25**. Add this vector and **+.033 Y** every pulling update. Only the first pulling update additionally adds **+.4000000059604645 Y** and sets boost. This is acceleration, not teleportation, constant-speed dragging, a moving tether or a charge drain per pull tick. The original applies it on server and client. Modern anti-floating uses the mapped `ServerGamePacketListenerImpl.f_9737_` field rather than changing flying abilities or general movement rules.

On the client only, amplitude increases **.02f** per flying update and multiplies by **.66f** per pulling update. The original has no special persistence override: inherited owner/position/motion may survive saving, but hand, pulling, boost, bind state, amplitude, previous-distance bucket and count reset. A loaded hook is therefore not falsely restored as a permanently attached offhand hook. Modern persistent ownership uses the native UUID representation instead of the old player-name string; transient hook state remains transient.

## Original rendering and modern tessellation

The native renderer uses the original `grappler.png`, converted original `ModelGrappler` cuboids and zero shadow. Hook yaw interpolates then subtracts 90 degrees; interpolated pitch rotates around Z. The additive camera-facing glow samples the original 32×32 particle atlas at column `1+ticks%6`, row 7, alpha **.21**, light **220**. Its base radius is **.5** with `1+sin(ticks/5)*.2+.2` scale.

The rope's centerline follows released `calcPoints`: interpolated owner/hook positions, first-person hand offsets, current look divided by five, owner eye-height/2.6 and body-height/2; `length=(float)(end.length*5)` and integer `steps`; interior sine offsets divide distance by 10, 8 and 6 with original amplitude and taper `1-i/(steps*1.25f)`. The origin and repeated final points remain GLE support points. Third-person uses the original body endpoint; the source does not inspect which other item the player currently holds to decide whether the rope exists.

Original GLE requests four tube sides, radius **.025**, join flags **1042**, texture step **2** and phase `length-points.size()`, using `rope.png`. The removed immediate-mode/GLE API is adapted to native buffered four-sided tube tessellation with angle-bisector joins, caps, bounded miter length and transported normals. This preserves ordinary centerline sampling, radius, four-sided silhouette and texture progression; it is **not a claim of binary-identical GLE triangulation, caps or lighting normals**. Malformed ropes beyond 4096 samples are bounded instead of allocating unbounded geometry. The client smoke/visual audit must establish the actually rendered frames and draw counters; source constants alone do not establish a visible rope in gameplay.

## Modern ownership and callback contract

Active owner links are qualified by actual Level and UUID rather than the legacy process-global numeric entity map. Removed hooks are purged without allowing a stale hook's cleanup to erase its replacement. Level unload and player logout release their links. Server work rejects dead, removed, spectator or different-world owners. Projectile motion/collision endpoint scans use bounded already loaded chunk checks; an unavailable ray is discarded without forcing a chunk. This scope does not certify arbitrary native portal handling or an addon's own callbacks as incapable of loading chunks.

The gun reserves its charge before a real Forge entity-join callback, prevents reentrant use from paying/spawning twice, and keeps an uncommitted hook from ticking, binding or pulling before a real accepted spawn and stable payment. Canceled/replaced provisional hooks are discarded. If the exact original physical ItemStack still matches its detached reserved bytes, its own charge/tag snapshot is refunded even after a callback moves it to another inventory slot or replaces the hand. This does not mutate the callback's foreign hand. An independently changed original stack is not overwritten with a stale complete NBT snapshot. Impact uses the real Forge projectile-impact cancellation event; a veto keeps the hook flying and does not bill another charge.

Independent read-only review identified and root implemented three protections before final verification: explicit `setOwner(null)` now marks ownership cleared and prevents modern Projectile's retained UUID/cache from reviving a revoked owner; owner changes/reloads release the old link and advance a revision to invalidate a captured in-progress owner plan; and a moved unchanged physical gun now receives its exact canceled-shot refund. A cleared owner is omitted from subsequent native saves. An absent-Owner reload explicitly keeps ownership cleared and tracked owner ID -1: modern Projectile otherwise clears its cache only when an Owner UUID is present. The existing explicit-clear regression also reloads its ownerless save into the same previously owned object, ensuring its old cached identity cannot revive. After the real Forge impact callback, the entity verifies its original Level, owner revision, owner identity and authoritative liveness/spectator state before binding, moving or applying force. A callback-owned new owner never receives force intended for the previously cached actor. Three new regression definitions cover moved-slot cancellation, explicit owner clearing/reload, and impact-time clearing/replacement with another living actor. These statements describe reviewed source, **not an unexecuted claim that repaired tests passed**.

## Prepared checks and observed earlier failure limits

The initial core suite contained **16 prepared tests**; reviewed ownership fixes expand it to **19 prepared tests**. The initial coverage is original item/charge/creative behavior; empty use; offhand payment; canceled/provisional spawning; reentry; callback hand replacement; literal muzzle/owner velocity; native block impact; entity-position/no-damage/fixed anchor; Forge impact veto; first boost/fall reset; flight versus attached sneak release; strict 30/31 flight limit; delayed owner-hook replacement; loaded/reequip behavior; and transient save state. The three additional definitions cover the callback protections above. Raw charge, actors and isolated terrain are explicit fixtures. Region tickets and actual entity/block readiness are bounded and owned by each isolated arena, with idempotent cleanup.

Initial server1 completed **1556 required tests with four failures**, native exit **4** and Gradle exit **1**; it is retained as a failed attempt. Two were `flyingHookSurvivesThirtyUpdatesAndExpiresOnThirtyFirst` and `entityImpactAnchorsAtEntityPositionWithoutDamageOrFollowingTarget`. Their fixture called `g.tick()` directly, which does not advance native modern `tickCount`: `Entity.tick()` delegates to `baseTick`, whereas `ServerLevel.tickNonPassenger` increments it at offsets 9–16 before invoking the entity. This directly explains the age assertion and makes the `<2` initial collision-ignore branch remain active during manually repeated updates. The corrected fixtures use actual native `level.tickNonPassenger` updates while preserving the original age/impact predicates. These local native callbacks test entity semantics; they do not by themselves claim elapsed world ticks or a full natural-flight session.

The other two failures were `paidTipAndSpoolArePhysicallyConsumedIntoOneFreshUnchargedGun` and `threeNativeRecipesMatchPinnedOriginalBookGridsAndPrimalPrices`. Both used the same mistaken Aqua/Terra test vectors. Original ConfigRecipes and already correct recipe JSON charge Tip **Terra1** and Spool **Aqua1**; `ArcaneModule.PRIMALS` orders Aer, Ignis, Aqua, Terra, Ordo, Perditio, so the correct vectors are `[0,0,0,1,0,0]` and `[0,0,1,0,0,0]`. Root corrected only those vectors and strengthened the diagnostic assertion. Original recipes and prices were not changed to fit a fixture. See the separate progression audit. These source-established four fixture errors require a fresh complete native run after correction; no corrected execution is inferred from their diagnosis.

No initial test declaration or this audit is an unexecuted pass claim. Root records the final actual test counts, failed/aborted attempts, source hashes, native exits, hidden-client captures and final artifact bindings in `VALIDATION.md` and the 0.38 artifact report. Prepared tests are not a complete ordinary-survival, multiplayer, client reload, audible-sound or arbitrary-addon compatibility proof. Native client QA must earn/pay the target research, real recipes and actual item charge before testing a normal shot; supplied precursors, raw aura/materials/actors remain explicitly declared fixtures.
